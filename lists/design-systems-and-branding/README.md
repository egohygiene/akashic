# Awesome Design Systems and Branding [![Awesome](https://awesome.re/badge.svg)](https://awesome.re)

> Design-system foundations, public implementations, design tokens, governance, accessibility, brand guidelines, content standards, and reference-quality identity systems.

Part of [akashic](../../README.md), the Ego Hygiene knowledge collection.

Use brand pages as references, not as asset libraries for imitation. Logos, typefaces, illustrations, product names, and other brand elements remain subject to each owner's trademark, copyright, and usage rules.

## Foundations and Learning

- [Atomic Design](https://atomicdesign.bradfrost.com/) - Brad Frost's freely readable book describing interfaces as nested atoms, molecules, organisms, templates, and pages.
- [Design Systems 101](https://www.nngroup.com/articles/design-systems-101/) - Nielsen Norman Group introduction distinguishing design systems from pattern libraries and style guides while explaining their core elements and benefits.
- [Design Systems Handbook](https://www.designbetter.co/design-systems-handbook) - Free DesignBetter handbook covering system creation, cross-functional workflows, documentation, adoption, and maintenance; an account may be requested for some formats.
- [Design Systems vs. Style Guides](https://www.nngroup.com/videos/design-systems-vs-style-guides/) - Short Nielsen Norman Group explanation of the difference between a complete reusable system and narrower presentation guidance.
- [Design Tokens Community Group](https://www.designtokens.org/) - Community stewarding a vendor-neutral format for exchanging named design decisions across tools and platforms.
- [Figma Design Tokens Resource Library](https://www.figma.com/resource-library/design-tokens/) - Practical overview of token naming, variables, modes, semantic layers, and design-to-code synchronization.
- [Inclusive Components](https://inclusive-components.design/) - Free reference explaining how common interface patterns can be designed and implemented for accessibility from the beginning.
- [Sparkbox Design System Maturity Model](https://sparkbox.com/foundry/design_system_maturity_model) - Framework for assessing a system's practices, process, tooling, governance, and organizational adoption over time.
- [Storybook Design Systems for Developers](https://storybook.js.org/tutorials/design-systems-for-developers/) - Guided tutorial for packaging, documenting, testing, and distributing a component library with Storybook.
- [USWDS Maturity Model](https://designsystem.digital.gov/maturity-model/) - Incremental model for adopting shared principles, experience guidance, and production code without requiring an all-at-once migration.
- [Zeroheight Design-System Governance Models](https://help.zeroheight.com/hc/en-us/articles/36474270188699-Design-system-governance-models-and-which-is-right-for-your-organization) - Comparison of centralized, federated, and hybrid ownership structures for maintaining a system; Zeroheight is a commercial platform.

- [DesignSystems.One](https://www.designsystems.one/design-systems) - Visual library of real-world systems with structured comparisons of foundations, components, technology stacks, and resources.
- [Designsystems.surf](https://designsystems.surf/) - Browsable catalog and editorial reference for studying public design systems, their foundations, and implementation choices.
- [Standards](https://standards.site/) - Commercial brand-guideline publishing platform whose public examples provide references for organizing living identity documentation.
- [Style Guides.io](https://styleguides.io/) - Long-running collection of style guides, pattern libraries, books, podcasts, tools, and design-system examples.
- [The Component Gallery](https://component.gallery/) - Cross-system gallery for comparing how public design systems name, document, and implement common interface components.

## Tokens, Tooling, and Accessibility

- [Accessible Palette](https://accessiblepalette.com/) - Browser tool for creating color systems with controlled perceptual lightness and WCAG contrast relationships.
- [Chromatic](https://www.chromatic.com/) - Commercial service for publishing Storybooks, reviewing visual changes, testing UI states, and collaborating on component libraries; a limited free plan is available.
- [Design Tokens Format Module](https://www.designtokens.org/tr/drafts/format/) - Community Group specification for portable token files, types, groups, aliases, color spaces, and cross-tool interchange; it is not a W3C Recommendation.
- [EightShapes Contrast Grid](https://contrast-grid.eightshapes.com/) - Free browser matrix for testing many foreground and background color pairs against WCAG contrast thresholds.
- [Open UI](https://open-ui.org/) - Open community research on interoperable interface-control names, anatomy, behavior, and styling that can inform web standards and design systems.
- [Specify](https://specifyapp.com/) - Commercial design-token engine for collecting, transforming, distributing, and synchronizing design decisions across tools and codebases.
- [Style Dictionary](https://styledictionary.com/) - Open-source build system for transforming shared design tokens into platform-specific code, assets, and documentation.
- [Supernova](https://www.supernova.io/) - Commercial design-system and knowledge-management platform for documentation, token pipelines, code generation, governance, and agent access.
- [Terrazzo](https://terrazzo.app/) - Open-source toolchain for validating design tokens and generating typed, platform-specific code and documentation from DTCG-compatible data.
- [Tokens Studio](https://tokens.studio/) - Design-token platform and Figma tooling for managing variables, themes, modes, synchronization, and design-to-code workflows; free and paid capabilities differ.
- [Web Content Accessibility Guidelines 2.2](https://www.w3.org/TR/WCAG22/) - W3C Recommendation defining testable accessibility requirements and conformance criteria for web content.
- [WhoCanUse](https://www.whocanuse.com/) - Free visualization tool that explains how a color contrast choice may affect people with different visual conditions.
- [Zeroheight](https://zeroheight.com/) - Commercial platform for documenting, delivering, measuring, and governing design systems across Figma, Storybook, code, and AI workflows.

## Brand Guidelines and Reference Pages

- [Canva Brand Guidelines Guide](https://www.canva.com/docs/brand-guidelines/) - Practical structure, checklist, examples, and editable templates for documenting a visual and verbal identity; some creation features require an account or paid plan.
- [Convex Brand Guidelines](https://www.convex.dev/brand) - Developer-product brand page covering official marks, usage, spacing, colors, typography, illustrations, and downloadable assets.
- [Discord Brand Assets](https://discord.com/branding) - Distinctive reference for logo hierarchy, clear space, a compact color system, banners, and explicit trademark-use boundaries.
- [Dropbox Brand Guidelines](https://brand.dropbox.com/) - Highly visual living system connecting strategic pillars with voice, logo, typography, iconography, color, imagery, and motion.
- [Figma Brand Guidelines](https://www.figma.com/using-the-figma-brand/) - Official naming, logo, product-lockup, color, and trademark guidance for referencing Figma and its products.
- [GitHub Brand Toolkit](https://brand.github.com/) - Deep public toolkit spanning identity attributes, logo, typography, color, illustration, mascots, layouts, textures, motion, voice, and applications.
- [Greptile Brand Guidelines](https://www.greptile.com/design) - Compact developer-tool reference page for logo marks, wordmarks, typography, colors, and downloadable assets.
- [Hugging Face Brand Assets](https://huggingface.co/brand) - Public assets and usage guidance for Hugging Face logos, the emoji mark, colors, typography, and partner references.
- [Linear Brand Guidelines](https://linear.app/brand) - Minimal reference showing how naming, generous clear space, monochrome marks, a restrained palette, and selective assets can create a coherent identity.
- [Mailchimp Brand Assets](https://mailchimp.com/about/brand-assets/) - Concise example of a character-led system documenting naming, mascot and wordmark relationships, colors, clear space, and prohibited uses.
- [NASA Brand Center](https://www.nasa.gov/nasa-brand-center/) - Official standards and legal boundaries for NASA insignia, logotype, identifiers, merchandise, media, and partner use.
- [Neon Brand Guidelines](https://neon.com/brand) - Developer-platform identity page with current logos, light and dark variants, usage rules, and downloadable assets.
- [OpenAI Design Guidelines](https://openai.com/brand/) - Public visual and trademark guidance for OpenAI, ChatGPT, GPT names, wordmarks, symbols, typography, color, and photography.
- [PostHog Brandbook](https://posthog.com/handbook/brand/foundations) - Unusually transparent operational brand system connecting taste, visual identity, voice, real-world applications, ownership, approvals, and assets.
- [Resend Brand Kit](https://resend.com/brand) - Focused reference for naming, logo construction, clear space, colors, type, downloadable assets, and a developer-oriented identity.
- [Slack Media Kit](https://slack.com/media-kit) - Gateway to Slack's official logos, color, typography, writing, illustration, photography, and brand-use guidance; some assets are hosted through Brandfolder.
- [Spotify Design and Branding Guidelines](https://developer.spotify.com/documentation/design) - Detailed rules for attribution, logo variants, minimum sizes, exclusion zones, color, naming, and integrating Spotify content.
- [Stripe Newsroom Assets](https://stripe.com/newsroom/information) - Restrained asset library for official logos, product badges, screenshots, leadership imagery, and trademark-use terms.
- [Supabase Brand Assets](https://supabase.com/brand-assets) - Compact asset page for official wordmarks, light and dark logo variants, integration buttons, and strict modification rules.
- [Vercel Brand Guidelines](https://vercel.com/geist/brands) - Brand and trademark system integrated directly into Geist, with assets, code examples, spacing, naming, permitted uses, and misuse guidance.
- [Webflow Brand Assets](https://brand.webflow.com/brand-assets) - Visual reference connecting a bright expressive brand palette and assets with a more restrained product-interface palette and usage rules.

## Content, Voice, and Brand Operations

- [Atlassian Content Guidelines](https://atlassian.design/content/) - Product-content guidance connected to Atlassian's broader design system and experience principles.
- [GOV.UK Writing Standards](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/) - Public guidance for designing clear, accessible, user-needs-driven content, including structure, tone, taxonomy, and policy-change communication.
- [Mailchimp Content Style Guide](https://styleguide.mailchimp.com/) - Public, Creative Commons-licensed guide to goals, voice, grammar, inclusive language, accessibility, translation, legal content, and channel-specific writing.
- [Microsoft Writing Style Guide](https://learn.microsoft.com/en-us/style-guide/welcome/) - Public technology-writing reference emphasizing warm, relaxed, crisp, clear, bias-aware, and globally adaptable communication.
- [PostHog Voice and Tone](https://posthog.com/handbook/brand/tone) - Concrete voice rules and before-and-after examples for headlines, product copy, errors, email, social media, and anti-jargon editing.
- [Resend Brand Voice and Tone](https://resend.com/handbook/marketing/what-is-our-brands-voice-and-tone) - Public developer-company guidance for translating brand principles into direct, technical, and consistent language.
- [Webflow Design Guidelines](https://brand.webflow.com/design-guidelines) - Application-level guidance for using Webflow's color, typography, composition, imagery, and visual effects consistently across brand surfaces.
